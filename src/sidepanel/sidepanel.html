What's New
v1.16.0Local-perception cost round: warm-up + OCR memo
  • Cold-start eliminated from the capture path: a privacy session now warms the YOLO + ViT pipelines in the offscreen runtime the moment it starts (VISION_WARMUP, fire-and-forget, non-fatal) — the first capture pays inference only, not the one-time model download + compile (cold-cache ViT load measured 37.9 s on the reference hardware; that load dominated the real-VLM first-step sanitizeMs 41487).
  • OCR memo: visual-PII scan regions are reused for byte-identical captures with identical crop ROIs (2-entry LRU, boxes only, failed/skipped scans never cached, cfg.ocrMemo=false fail-safe switch, ocrMemoHit telemetry) — the warm unchanged-screen sanitize drops from ~1.2 s (full-frame OCR re-scan every time) to ~0.1 s.
  • run-e2e-real.mjs --warmup: one unmeasured cycle (zero VLM calls) before the measured scenarios, so real-VLM reports describe the steady state and are stamped meta.warmup — cold-start and steady-state numbers are never merged.
  • Honest negative result, measured: the detector-input downscale knob (yoloMaxEdge) is correctness-neutral (box parity IoU = 1.000) but latency-neutral — yolos-tiny resizes internally to a fixed resolution. See OpenCometBench/probe-yolo-downscale.mjs. The changed-frame fix levers are the memos + warm-up, not input size.
v1.15.9Real-VLM E2E for free cloud models
  • The REAL-VLM E2E tier is now verified against OpenRouter free vision models: measured reference run — inclusionai/ling-3.0-flash-vl:free, scenario find-and-open: 1/1 verified action, privacy blocks 0, true VLM leg 4679 ms; full report archived in OpenCometBench/results/.
  • Reliability fixes in run-e2e-real.mjs: the extension service worker is now discovered LIVE (authoritative ID from the running worker, not a hash guess) and the pre-run endpoint check sends the Bearer header for hosted providers.
  • New pre-flight smoke: OpenCometBench/e2e/smoke-openrouter-free.mjs — one 1×1 px image + JSON instruction, measured TTFB, named failure hints (401/402/429/404). Keys come from the OPENROUTER_API_KEY env var — never hardcoded, never printed, never committed.
v1.15.8Safe prose is no longer black-boxed
  • Fix: the sanitized screenshot could draw black boxes over SAFE text that merely mentions secret words — "three literal token formats", "four surviving secret families:", "Google key contiguity,". Root cause: the assignment detector's digit lookahead scanned to the END of the page text, so any digit anywhere later ("v1.15.3", "22/22") armed a false match.
  • The digit/letter requirement is now bounded to the candidate value itself — a real assignment ("token=eyJ…", "password: hunter2", "api_key = sk-live-…") still redacts exactly as before.
  • The same tightening applies to the outbound text sweep, so safe phrases also reach the model unmasked and page summaries read naturally.
v1.15.7Privacy firewall: summarize survives secret-shaped pages
  • Fix: a summarization task on a long page could die before the first AI call with "Privacy firewall BLOCKED the network request: secret-shaped text survived sanitization". Root cause: the outbound gate and the prompt read the pipeline's DOM text, whose PII scan covers only the first 8,000 characters — a key-shaped string deeper in the page tripped the gate and the old policy aborted the WHOLE turn.
  • The gate and prompt now read the firewall envelope's fully-swept canonical text (the same rule the companion-server path has followed since v1.14).
  • Upgraded last-line policy — redact-and-verify: any remaining secret-shaped fragment is masked locally to [REDACTED:secret], re-verified, and only provably clean text is transmitted. Fail-closed preserved: if something cannot be masked, the request is still refused.
  • Gate block messages now name the offending field and detection pattern (never the value) so reports are debuggable.
v1.15.6Final answers delivered + Profile custom info
  • Summarize / question tasks now deliver the model's FULL answer as the final response — no more bare "Task complete" with no summary.
  • Settings → Profile gains Custom info: add your own label/value fields and the agent uses them for form filling and answers about you.
v1.15.5About page (this page)
  • New Settings → About page: live version read from the loaded manifest, what's-new history and project details.
  • UI-only release — the privacy/detection pipeline is byte-identical to v1.15.4.
v1.15.4Avatar guard + pixel-only OCR
  • CSS background-image avatars are redacted by a heuristic avatar guard; model-confirmed faces still stand down.
  • Person-name fields (full name, father's/mother's name, card-holder…) are label-aware and redacted.
  • Pixel-only PII: visible canvases get targeted ×2-upscaled OCR re-reads plus a structural battery; DOM text walker budget 140 → 400.
v1.15.3Small profile photos — DOM-guided face sweep
  • Every visible image ≥24px is cropped, upscaled (a 64px avatar face becomes ~200px) and re-checked by the on-device face model.
  • Model-confirmed only: logos and icons are scanned and left untouched — no blanket blurring.
v1.15.2Indian ID expansion + live scorecard

  • SIH Scorecard gains a LIVE per-task privacy report that fills in automatically after each completed task.

Project Details
Problem
Smart India Hackathon PS #26171 — "On-device Visual Perception for Light-weight Browser Agents".
Organisation
Indian Space Research Organisation (ISRO), Department of Space.
Build
Chrome MV3 extension · side panel + service worker + offscreen ML runtime.
On-device
MediaPipe BlazeFace (faces) · Transformers.js YOLO/ViT (visual context) · Gemma 4 via WebGPU (local brain) · vendored OCR for pixel-only PII.
Benchmark
OpenComet-Bench — 922 scored cases across four tiers: 216-case leakage fuzz · 23-case adversarial wire-capture E2E · 72-run browser redaction matrix · 514-case checksum-validated PII corpus.
Privacy
Raw screenshots never leave the browser — only sanitized pixels, redacted DOM text and a redaction manifest reach the configured model.
