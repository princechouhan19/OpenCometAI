# v1.29.0 — Streaming failure ladder + diagnostics guide + source cleanup (2026-09-21)

The OpenAI-compatible provider (kimi / deepseek / glm / custom gateways) no
longer hangs or returns a dead-empty answer on **thinking models**. The
diagnostics guide is rewritten around a real captured run. And the whole
source tree went through a comment-discipline pass: version-history narration
is gone from code — the changelog and commit history carry it instead.

## Upgraded DOM element detector with visual tagging (src/content/dom-detector.js)

Element identification was rebuilt around the upgraded dom-detector: a full-page
traversal that finds interactive elements a tag-selector scan cannot see, and
paints them with boxes + numeric badges so the model and the screenshot share
one identity per control.

- **Cursor-first interactivity** — computed `cursor` style is the strongest
  signal, before tag/role/contenteditable/event-attribute checks. Custom
  widgets (player controls, chips, cards built as `<div>`) now register.
- **Shadow DOM and same-origin iframes** traversed inline; iframe item
  bounds are reported in page coordinates via cumulative offsets.
- **Top-element guard** — `elementFromPoint` at the centre and corners
  drops controls hidden behind modal backdrops, sticky headers and cookie
  bars; ARIA menu containers stay exempt (options render over content).
- **Distinct-interaction rule** — nested interactives collapse into their
  parent unless they act on their own, killing duplicate badges per control.
- **Element items carry an xpath** alongside the existing `uid`/`domPath`
  keys; relocation order everywhere is live registry (reaches shadow-root
  content, survives SPA re-renders) → uid attribute (main document +
  accessible iframes) → xpath → previous fallback chain (`domClick`,
  `domType`, `domScrollToUid`).
- The legacy inline tag-scan in `getPageInfo` remains as the fallback path
  and still supplies readable text, headings, tables and scroll state.

## Streaming failure ladder (providers.js)

Thinking models can spend minutes on invisible reasoning and then deliver
**zero visible text**: the request returns `200 OK`, the SSE stream stays
open, and the run fails with "Empty response from AI" after ~290 s
(observed on `qwen3-vl-235b-a22b-thinking` behind a custom gateway).

`callOpenAICompatible` now guards every attempt:

- **45 s idle watchdog** — a stream silent for 45 s is aborted
  (`stream idle > 45s`).
- **150 s per-attempt cap** — headers + body, enforced through an
  `AbortController`.
- **300 s total budget** for the whole ladder
  (`gave up after 300s total`).
- **Escalation on empty/stalled attempts**, visible in the attempt tag:
  `s1r0j1` (first try) → `s1r0j1·x2` (token budget ×2, capped at 16000) →
  `s1r0j1·x2-nothink` (`enable_thinking:false` + `chat_template_kwargs`,
  the vLLM and DashScope spellings) → next rung → **non-streaming
  fallback**.
- Only `400`/`422` walk down the rungs (unknown-parameter rejection);
  auth/rate/network errors still throw immediately.
- **Credit-fit refit (402)** — pay-as-you-go gateways (OpenRouter) reject a
  request whose `max_tokens` exceeds the balance and state the affordable
  count (`…can only afford 544`). The cap is refitted to 85% of that count
  and the same rung retried, so a low balance degrades the output ceiling
  instead of killing the run; a balance that cannot fund ~256 output tokens
  fails fast with the top-up URL.
- When the model name contains `-thinking`, the escalation log suggests the
  `-instruct` variant of the same model (in the field: 1–4 s per turn).

Covered by `scripts/test_v1290_streaming_guards.mjs` (13 checks): empty-everywhere
ladder exhaustion, recovery on the first escalation, stalled-stream fallback,
400-on-thinkOff tolerance, 401 short-circuit, and total-budget bounding.
`scripts/test_creditfit_402.mjs` (10 checks) covers the refit path: same-rung
retry at the fitted cap, cap persistence across the x2 escalation, fast
failure below the minimum, plain-402 hint, and 400-ladder regressions.

## Diagnostics guide rebuilt (docs/guides/DIAGNOSTICS_LOGGING.md)

The guide now documents the logging system as it exists today, built around a
real captured run: log-line anatomy, namespaces, a line-by-line walkthrough of
a full run (boot → planner → VLM turn → execution → honest failure), the
`[VLM-REQ] / [VLM-RAW] / [VLM-RES]` groups, the v1.29.0 failure-ladder lines,
privacy-pipeline log lines, the failure-kind table, and how to export logs.

## Interactive documentation (Mermaid)

Every core diagram is now Mermaid inside the Markdown, so GitHub renders it
natively and interactively:

- **README.md** — architecture (browser contexts ↔ AI backends), the agent
  run loop (guardian → sandbox → sanitize → decide → execute → verify), and
  the privacy pipeline from raw frame to network.
- **docs/architecture/PRIVACY_VISION.md** — module dependency graph (was
  ASCII art), the PII detection taxonomy (what catches what, checksum
  arbitration), and the six-stage face-recall cascade.
- **docs/guides/DIAGNOSTICS_LOGGING.md** — a full VLM decision turn as a
  sequence diagram (VLM-REQ → stream → TTFT → VLM-RAW → VLM-RES) and the
  streaming failure ladder as a flowchart, including the 402 credit-fit refit.
- **docs/guides/DOM_DETECTOR.md** (new) — the upgraded dom-detector end to
  end: detection pipeline, the badge ↔ uid contract, and the four-stage
  relocation chain behind every click.
