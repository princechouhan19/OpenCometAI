# v1.29.0: streaming failure ladder, diagnostics guide, source cleanup (2026-09-21)

The OpenAI-compatible provider no longer hangs or returns a dead-empty answer on
thinking models. The diagnostics guide is rewritten around a real captured run.
The source tree went through a comment-discipline pass; version history lives in
this changelog and in git rather than in code comments.

## DOM element detector with visual tagging (`src/content/dom-detector.js`)

Element identification was rebuilt around a full-page traversal that finds
interactive elements a tag-selector scan cannot see, and paints them with boxes
and numeric badges so the model and the screenshot share one identity per
control.

- **Cursor first.** The computed `cursor` style is the strongest signal, checked
  before tag, role, contenteditable and event-attribute rules. Custom widgets
  such as player controls, chips and cards built as `<div>`s now register.
- **Shadow DOM and same-origin iframes** are traversed inline, with iframe item
  bounds reported in page coordinates through cumulative offsets.
- **Top-element guard.** `elementFromPoint` at the centre and corners drops
  controls hidden behind modal backdrops, sticky headers and consent bars. ARIA
  menu containers stay exempt, because their options render over content.
- **Distinct-interaction rule.** Nested interactives collapse into their parent
  unless they act on their own, which removes duplicate badges per control.
- **Relocation order.** Element items carry an xpath alongside the existing
  `uid` and `domPath` keys. Everywhere, resolution is live registry first, which
  reaches shadow content and survives SPA re-renders, then the uid attribute in
  the main document and accessible iframes, then xpath, then the previous
  fallback chain: `domClick`, `domType`, `domScrollToUid`.
- The legacy inline tag scan in `getPageInfo` remains the fallback and still
  supplies readable text, headings, tables and scroll state.

## Streaming failure ladder (`providers.js`)

Thinking models can spend minutes on invisible reasoning and then deliver no
visible text: the request returns `200 OK`, the stream stays open, and the run
fails with "Empty response from AI" after about 290 s. This was observed on
`qwen3-vl-235b-a22b-thinking` behind a custom gateway.

`callOpenAICompatible` now guards every attempt:

- A **45 s idle watchdog** aborts a silent stream (`stream idle > 45s`).
- A **150 s per-attempt cap** covers headers and body through an
  `AbortController`.
- The **whole ladder** has a 300 s budget (`gave up after 300s total`).
- An **empty or stalled attempt escalates**, visible in the attempt tag:
  `s1r0j1` first try, then `s1r0j1·x2` with the token budget doubled and capped
  at 16000, then `s1r0j1·x2-nothink` with `enable_thinking: false` and
  `chat_template_kwargs`, the vLLM and DashScope spellings, then the next rung,
  then the non-streaming fallback.
- Only `400` and `422` walk down the rungs. Auth, rate-limit and network errors
  throw immediately.
- **Credit-fit refit on 402.** Some gateways reject a `max_tokens` the balance
  cannot cover and state the affordable count. The cap is refitted to 85% of
  that count and the same rung retried, so a low balance lowers the output
  ceiling instead of killing the run. A balance that cannot fund about 256
  output tokens fails fast with the top-up URL.
- When the model name contains `-thinking`, the escalation log suggests the
  `-instruct` variant, which in the field answered in 1 to 4 s per turn.

Covered by `scripts/test_v1290_streaming_guards.mjs` (13 checks): ladder
exhaustion when every attempt is empty, recovery on the first escalation,
stalled-stream fallback, tolerating a 400 on `thinkOff`, short-circuiting on
401, and total-budget bounding. `scripts/test_creditfit_402.mjs` (10 checks)
covers the refit path: same-rung retry at the fitted cap, cap persistence across
the ×2 escalation, fast failure below the minimum, the plain-402 hint, and
400-ladder regressions.

## Diagnostics guide rebuilt

`docs/guides/DIAGNOSTICS_LOGGING.md` now documents the logging system as it
exists, built around a real captured run: log-line anatomy, namespaces, a
line-by-line walkthrough from boot through planner, model turn, execution and
failure, the `[VLM-REQ]`, `[VLM-RAW]` and `[VLM-RES]` groups, the failure-ladder
lines, privacy-pipeline lines, the failure-kind table, and how to export logs.

## Interactive documentation

Every core diagram is now Mermaid inside the Markdown, so GitHub renders it.

- `README.md`: architecture, the agent run loop, and the privacy pipeline from
  raw frame to network.
- `docs/architecture/PRIVACY_VISION.md`: module dependency graph, replacing
  ASCII art, the PII detection taxonomy and the six-stage face cascade.
- `docs/guides/DIAGNOSTICS_LOGGING.md`: a model decision turn as a sequence
  diagram, and the failure ladder as a flowchart including the 402 refit.
- `docs/guides/DOM_DETECTOR.md`, new: the detector end to end, the badge-to-uid
  contract, and the four-stage relocation chain.

## Comment discipline

Every first-party file was reviewed and about 600 lines of comment noise
removed: version-history narration, change-incident narration and captured field
log quotes, full-width banner rules reduced to plain headers, and duplicated or
restating lines. No behaviour changed; the pass touched comments only, apart
from the provider ladder and the guide above.
