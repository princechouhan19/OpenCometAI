# v1.29.0 — Streaming failure ladder + diagnostics guide + source cleanup (2026-09-21)

The OpenAI-compatible provider (kimi / deepseek / glm / custom gateways) no
longer hangs or returns a dead-empty answer on **thinking models**. The
diagnostics guide is rewritten around a real captured run. And the whole
source tree went through a comment-discipline pass: version-history narration
is gone from code — the changelog and commit history carry it instead.

## Streaming failure ladder (providers.js)

Thinking models can spend minutes on invisible reasoning and then deliver
**zero visible text**: the request returns `200 OK`, the SSE stream stays
open, and the run fails with "Empty response from AI" after ~290 s
(observed on `qwen3-vl-235b-a22b-thinking` behind a custom gateway).

`callOpenAICompatible` now guards every attempt:

- **45 s idle watchdog** — a stream silent for 45 s is aborted
  (`stream idle > 45s`).
- **150 s per-attempt cap** — headers + body, enforced through an
  `AbortController`.
- **300 s total budget** for the whole ladder
  (`gave up after 300s total`).
- **Escalation on empty/stalled attempts**, visible in the attempt tag:
  `s1r0j1` (first try) → `s1r0j1·x2` (token budget ×2, capped at 16000) →
  `s1r0j1·x2-nothink` (`enable_thinking:false` + `chat_template_kwargs`,
  the vLLM and DashScope spellings) → next rung → **non-streaming
  fallback**.
- Only `400`/`422` walk down the rungs (unknown-parameter rejection);
  auth/rate/network errors still throw immediately.
- When the model name contains `-thinking`, the escalation log suggests the
  `-instruct` variant of the same model (in the field: 1–4 s per turn).

Covered by `scripts/test_v1290_streaming_guards.mjs` (13 checks): empty-everywhere
l exhaustion, recovery on the first escalation, stalled-stream fallback,
400-on-thinkOff tolerance, 401 short-circuit, and total-budget bounding.

## Diagnostics guide rebuilt (docs/guides/DIAGNOSTICS_LOGGING.md)

The guide now documents the logging system as it exists today, built around a
real captured run: log-line anatomy, namespaces, a line-by-line walkthrough of
a full run (boot → planner → VLM turn → execution → honest failure), the
`[VLM-REQ] / [VLM-RAW] / [VLM-RES]` groups, the v1.29.0 failure-ladder lines,
privacy-pipeline log lines, the failure-kind table, and how to export logs.

## Source-wide comment discipline

Every first-party file was reviewed; ~600 lines of comment noise were
removed:

- version-history narration (`// v1.15.1 CONSOLE VISIBILITY…`,
  `// v1.19.0: …`) — change history lives in this changelog and in git;
- change-incident narration and captured field-log quotes;
- full-width banner/divider rules reduced to plain section headers;
- duplicated and restating comment lines.

No behavior change: this pass touches comments only, except the provider
ladder and guide above.
