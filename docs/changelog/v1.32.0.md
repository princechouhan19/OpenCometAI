# v1.32.0

CI/CD, a goal contract the model is actually asked for, and two provider-ladder
fixes. The privacy pipeline is unchanged: `privacy-firewall.js` and
`wire-guard.js` are untouched.

## Goal contracts are reachable now

v1.31.1 added `verifyTaskGoal()` and then never asked the model for a goal, so
every run closed as `completed_unverified`. The prompt now carries a `GOAL
CONTRACT` shape with the check vocabulary, and a run that ends without one is
asked **once** for a predicate before it may close.

- new response key `goal_checks`; `goal` stays the planning sentence, because
  overloading it would have silently broken the planning shape
- the ask travels through the same nudge channel as the guardian hint
  (`taskMemory.pendingGoalAsk`), consumed in `injectRuntimeNudges()`
- a second `done` is accepted and reported as `completed_unverified`, so a model
  that ignores the instruction costs one turn instead of looping

## Probe extracted and tested

`pageProbe()` in `src/lib/goal-probe.js`. It is self-contained because
`chrome.scripting.executeScript` serialises the function into the page and it
cannot see imports; the tests therefore run the exact source Chrome runs,
against a fake `document`. Covered: per-selector counts, first-text,
whitespace collapse, truncation at 500/20000, absent selector, invalid selector
(zero, never a pass), missing body, and a guard that the function imports
nothing.

## Provider ladder

Found by `scripts/test_creditfit_402.mjs`, which had been failing 9 of 10
assertions:

- a `400` naming `response_format` used to cost two calls: first the prompt-cache
  ladder restart (re-sending the breakpoint to a gateway complaining about a
  different field), then a rung that still carried `response_format`. The ladder
  now jumps to the first rung without it, and the cache restart only fires when
  the error looks like a cache-shape complaint.
- on a ~26-turn task, one wasted call per rejection is paid on every run.

## CI/CD

`.github/workflows/ci.yml`: unit tests on Node 20 and 22, benchmark suites,
comment-style gate, version-drift check, a packaging job that runs
`scripts/package.sh` and uploads `dist/*.zip`, and a job running the six
no-browser regression harnesses. No `npm ci` — the extension has no
dependencies.

`.github/workflows/release.yml`: on a `v*` tag, assert the tag matches
`manifest.json`, build through the same gates, attach the zip to the release.
The Web Store upload stays manual.

`scripts/check-style.sh`: fails the build on comment patterns that read as
generated prose (`WHY THIS EXISTS`, `fail-honest`, `PURSUANT TO`, LLM
self-reference). Long comment blocks are reported with `file:line` but do not
fail — the tree still has about forty of them in files nobody has reviewed.

## Not done

- the eight Playwright suites in `scripts/` are still not in CI: they need a
  browser install and are tied to specific vendored models, so they need triage
  first
- `debugger` is still a default permission
- perception latency is untouched; `objectDetect` ~7.8 s and `ocr` ~3.4 s still
  dominate a ~12.9 s changed-frame pass
- `bench-gate.yml` currently reports `FAIL (2 regressions)` on p95 drift across
  sub-millisecond suites (0.16 → 0.233 ms). That is timing noise on ~0.2 ms
  work; the fix is to widen the floor for microbenchmarks rather than loosen the
  gate
- `src/background/sw.js` still cannot be imported by a test, which is why the
  Retry-After bug survived as long as it did. Extracting the per-iteration
  decision is the next structural change
