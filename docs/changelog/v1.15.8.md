# v1.15.8: safe prose is no longer black-boxed

Field report on v1.15.7 in privacy mode: the sanitized screenshot drew black
boxes over prose that merely mentions secret vocabulary, such as "three literal
▮token formats▮", "the four surviving ▮secret families:▮" and "(Google ▮key
contiguity,▮ A4 split…".

The decision turn completed, so the redact-and-verify policy was working. The
damage was to the agent's own view: the model received a censored screenshot and
censored page text.

## Root cause

The secret-assignment patterns in `pii-detector.js` (`password` and `api_key`,
mirrored by the firewall's `password_assignment` and `token_assignment`)
anchored blob-unbounded lookaheads at the value start. `(?=.*\d)` requires a
digit anywhere later in the scanned string, and the OCR full-page reconstruction
is one newline-free blob, so "token formats" matched because "v1.15.3" sat
hundreds of characters later.

The `\s+` separator alternative also meant no equals sign or colon was required
at all. v1.15.7 had documented this coarseness ("Password: required for login.
Room 42." trips inside one blob) and accepted it because the text policy merely
masked. The canvas path paints real black boxes, so the class had to be fixed at
the pattern level.

## 1. Lookaheads bounded to the value

A digit, and a letter where specified, must now sit inside the candidate value:
`(?=[^\s'"]*\d)[^\s'"]{5,}` and
`(?=[A-Za-z0-9_.\-+/=]*\d)(?=[A-Za-z0-9_.\-+/=]*[A-Za-z])[A-Za-z0-9…]{6,}`.

Every real assignment still fires: `token=eyJ…`, `password: hunter2`,
`api_key = sk-live-…`, quoted forms, space-separated forms with digit-bearing
values, and labelled AWS literals.

## 2. Both channels fixed together

The detector patterns feed OCR-to-canvas redaction and DOM text masking. The
firewall sweep patterns govern the outbound wire text. One tightening across
four patterns keeps safe prose readable in screenshots and in page text.

## 3. The guarantee holds

The 216-case leakage fuzz, the security suite and the 514-case PII corpus re-ran
green with identical pass semantics, and every real-secret family still
matches. The fuzz generates digit-bearing values, so nothing depended on the
unbounded lookahead.

## 4. Verification

New `scripts/test_v1158_prose_safe.mjs` 27/27.

Part A, in Node: the three field phrases and the "Password: required … Room 42."
blob yield zero findings, having fired before the fix, which was reproduced
first. Twelve real-secret controls all fire through the detector, the sweep and
masking.

Part B, on the real unpacked extension: summarizing the prose-only fixture
(`OpenCometBench/e2e/pages/prose-discussion.html`, digits included) has OCR
scan 206 words and yield zero api_key or password regions, so no black boxes;
the run completes and the safe phrases reach the mock backend unmasked.

blob is no longer masked.
