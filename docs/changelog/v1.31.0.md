# v1.31.0: benchmark confidence intervals and a regression gate, cache stickiness, adversarial memory guard

Released 2026-10-05. Benchmark infrastructure, provider cache stickiness and
end-to-end reliability.

Verification: `scripts/test_v1310_verify.mjs` 56/56, OpenCometBench 6/6 pass,
regression gate pass against the committed v1.30.0 baseline, adversarial 23/23
in one invocation with per-case time to first decision, and an independent
re-run at 2026-10-05T17:11Z reproducing 6/6 with the gate passing and fuzz p95
6.8% below baseline.

Two non-goals, by decision: Chrome built-in AI (Gemini Nano, Prompt API) is not
integrated, and detector or OCR model swaps (YOLO26, PP-OCRv5) are deferred.
The swaps would change model internals and break the byte-identical quality gate
this release makes enforceable, and they need a device matrix before any claim
is honest.

## 1. Published latency numbers carry error bars

v1.30.0 measured every case; the claims were still point estimates. This release
adds the statistics layer over those 815 samples.

- **`bootstrapCi()`** in `OpenCometBench/latency.js` computes a deterministic
  percentile bootstrap confidence interval for any quantile, using a seeded
  mulberry32 generator, so the same samples yield the same interval on every
  run. Empty input stays `n=0`, following the same rule as `latencyStats`: a
  missing measurement is never fabricated.
- **`mannWhitneyU()`** provides a nonparametric rank-sum test with normal
  approximation and tie correction for A/B latency comparisons.
- **`run-all.js` attaches and prints the intervals.** Every suite's
  `metrics.latency` carries `ciP50` and `ciP95` at 95% with 1000 resamples, and
  the table prints lines like `p50=0.016ms [CI95 0.014–0.017]`, so overlapping
  intervals can be recognised as such.

## 2. A regression gate that enforces quality

`OpenCometBench/regression-gate.mjs` compares a current `run-all.js --json`
against the committed baseline
`OpenCometBench/baselines/v1.30.0-unit.json`:

1. Any change in a quality metric (precision, recall, F1, coverage, IoU,
   accuracy, leak counts) is a hard block. Latency fields are excluded.
2. A suite's p95 may grow by at most 25%, and only blocks when the per-case
   distributions actually shifted, by Mann-Whitney U at p < 0.01 two-sided.
   Machine noise no longer blocks releases, and real slowdowns no longer hide
   behind it.

`.github/workflows/bench-gate.yml` runs the six offline suites and the gate on
every push and pull request to `main`, uploading the result as an artifact. No
dependencies and no browser tier, because the Node tier is deterministic.

Measured on this release: the fuzz suite's p95 grew 40.4% against the baseline,
over the 25% budget, but the rank-sum test returned p = 0.103, so the gate
allowed it as noise. A naive threshold gate would have blocked the release; a
gate that ignored latency would have hidden a real slowdown.

## 3. Prompt cache stickiness on OpenRouter

The decision prompt was already cache-shaped: a byte-stable system prompt and
cache-friendly block ordering. This release completes the loop on the wire,
gated to `openrouter.ai`; generic OpenAI-compatible gateways see no change.

- **`session_id`.** A deterministic per-task FNV-1a hash (`sessionIdForTask`,
  `oc-<base36>`) with no task text, URL or PII leaving the device. OpenRouter's
  sticky routing uses it to pin every step of a run to the same cache-warm
  endpoint from the first turn.
- **`cache_control` on the system message.** The static policy prefix becomes
  explicitly cacheable, and OpenRouter translates the Anthropic-style marker per
  provider. A strict provider that rejects the shape gets one automatic clean
  retry of the full ladder without the breakpoint.
- **Cache telemetry.** `cached_tokens`, cache writes and the discount are
  normalised by `cacheUsageFrom`, logged, and surfaced through the `onUsage`
  payload, so a first real run produces measured hit rates.

## 4. ONNX Runtime threading, measured honestly

The vendored wasm was always the threaded build
(`ort-wasm-simd-threaded.asyncify.wasm`, 23.6 MB) but `numThreads` was pinned to
1 on a stale assumption about cross-origin isolation.

`ortThreadCount()` now feature-detects: SharedArrayBuffer present and the page
isolated means up to 4 threads, capped by `hardwareConcurrency`, otherwise
exactly 1, byte-identical to v1.30.0. The chosen count is exposed through
`getLocalVisionStats().threads`.

Measured on this release in the sandbox CI with 2 cores, the effect on
yolos-tiny is neutral. `OpenCometBench/probe-ort-threads.mjs` runs the real
vendored stack and model in a COOP/COEP-isolated page:

- 1 thread median 9850 ms, 2 threads 10106 ms (0.97×), 4 threads 9626 ms
  (1.01×), all within run-to-run noise.
- Box parity is identical across thread counts.
- This is consistent with the model resizing internally to a fixed 224 px
  resolution; the v1.16.0 downscale probe found IoU 1.000 and a latency ratio of
  0.99. YOLOS compute is fixed-size and not threading-friendly at this scale.

Recorded for the next planner: the honest levers for the 7 to 10 s changed-frame
YOLO leg are the memo and warm-up, which are shipped, and a detector model swap
such as YOLO26n, which is NMS-free and measured at 38.9 ms CPU ONNX at 640 px on
desktop-class cores, but first requires recalibrating the quality gate on its
outputs. The thread unlock stays, because it is free and safe and benefits the
ViT and NER pipelines.

## 5. Adversarial runs no longer exhaust memory

**Memory guard.** The runner kept one Chromium context alive across all 23
cases, including the extension, offscreen ML document, models and per-case
pages. Long runs ran out of memory around case 16, so full-run evidence had to
be assembled from isolated re-runs.

`--context-budget=N`, defaulting to 8, now rotates to a fresh context,
rebuilding the extension profile, service worker, settings and OCR toggles and
the helper page. A full 23/23 run completes in one invocation.

**Time to first decision.** Every case row carries `ttfaMs`, the interval from
task start to the first recorded `/agent/decide` arrival, covering capture,
perception, sanitize, gates and wire. Cold starts after a rotation appear in the
numbers rather than being averaged away.

The report `meta` records `contextBudget` and `contextRotations`, so the
execution shape is auditable from the evidence file alone.
