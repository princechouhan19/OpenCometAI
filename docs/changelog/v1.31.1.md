# v1.31.1

Loop reflection, goal verification, error classification. The privacy pipeline
is unchanged: `privacy-firewall.js` and `wire-guard.js` are untouched and the
network gate still runs on every outbound byte.

## Goal verification

`src/lib/goal-verifier.js` (new).

A run used to end as soon as the model returned `{type:'done'}`, or when a
heuristic guessed (a click on a "send" button that closed the compose dialog).
The model's own claim was the only evidence in the loop.

The navigator can now declare what done looks like:

```json
{ "checks": [
    { "check": "url_matches", "pattern": "#sent$" },
    { "check": "text_contains", "value": "Message sent" }
] }
```

`verifyTaskGoal()` reads the live page with `chrome.scripting.executeScript`
(url, title, body text, count and text for each selector in the contract) and
evaluates it.

| verdict | behaviour |
|---|---|
| `verified` | run ends, `completion: 'verified'` |
| `failed` | run continues; the failed check becomes an observation |
| `unevaluable` | run may end, `completion: 'completed_unverified'` |

Checks: `url_matches`, `url_contains`, `title_contains`, `text_contains`,
`text_absent`, `count_at_least`, `count_equals`, `element_exists`,
`element_text_contains`. A malformed check is dropped when the contract is
parsed, never treated as satisfied. A missing probe field gives `unevaluable`,
not a pass.

`MSG.AGENT_DONE` carries `data.completion`; existing consumers are unaffected.

Known gap: nothing yet requires the planner to emit `goal`. Without one the run
behaves as before and is labelled `completed_unverified`. `docs/ROADMAP.md`
item 2.

## Error classification

`src/lib/error-taxonomy.js` (new).

The catch block treated every failure the same and gave up after three
iterations, so a provider 502 counted as a task failure. Errors are now sorted
into `TRANSIENT_NETWORK`, `RATE_LIMIT`, `PROVIDER_5XX`, `AUTH`, `DOM_STALE`,
`TARGET_NOT_FOUND`, `PERCEPTION_FAILED`, `POLICY_BLOCKED`, `UNKNOWN`.

- transient / rate limit / 5xx: retry the same action, exponential backoff with
  +/-25% jitter, honouring `Retry-After`, three attempts, not counted as a step
  failure
- `DOM_STALE` / `TARGET_NOT_FOUND`: one immediate re-probe, no delay
- `AUTH` / `POLICY_BLOCKED`: terminal on the first attempt

Classification runs before `isFatalProviderError()`.

## Loop reflection

`src/lib/loop-reflection.js` (new), wired into the loop.

Three loop shapes are detected over ACTION steps: `repeat_action`,
`oscillation`, `dead_wait`. On detection the agent gets one reflection prompt
through the existing `pendingReflection` nudge channel, capped at three per run.
Detecting and throwing ended the task; reflecting keeps it working.

Called from `updateActionLoop` in `src/background/sw.js`; consumed in
`injectRuntimeNudges`.
