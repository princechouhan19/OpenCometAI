# v1.15.9: real-model end-to-end against free cloud models

The real-model end-to-end tier is now measured against OpenRouter free vision
models, the bring-your-own-key production path with no companion server.

Reference run on real hardware, 2026-09-10
(`OpenCometBench/results/e2e-real-benchmark-1789066449033.json`),
`inclusionai/ling-3.0-flash-vl:free`, scenario `find-and-open` ("Open the
Pricing page"):

| Metric | Measured |
|---|---|
| Verified action ratio | 1/1, `ACTION_VERIFIED` on title and content change |
| Execution and task success | 1.0 and 1.0 |
| Privacy blocks | 0 |
| `vlmMs_real` p50, inference and transport | 4679 ms |
| `actionMs` p50 | 777 ms |
| `sanitizeMs` p50, full live path, cold start | 41487 ms |
| Step total | 47000 ms |

Reading these honestly: this is the full live agent path with a real multimodal
model, from capture through on-device sanitize, the privacy gate, a live
OpenRouter call and a verified action.

The 41.5 s sanitize is the cold-start cost of this run and must not be merged
with, or substituted for, the warm unchanged-screen p50 of 1216 ms from the
browser report. Different conditions, different rows. It is also not the
bottleneck: the 4.7 s model leg is smaller.

An earlier attempt with `llama-3.2-11b-vision-instruct:free` finished 0 steps
(`e2e-real-benchmark-1789065225488.json`) and is kept as the negative control.

## Harness changes

`run-e2e-real.mjs` now discovers the extension service worker live, reading the
authoritative ID from the running worker instead of guessing a hash, because
Chrome canonicalizes unpacked paths before assigning IDs. It also sends the
Bearer header on the pre-run endpoint check for hosted providers.

A new pre-flight smoke, `OpenCometBench/e2e/smoke-openrouter-free.mjs`,
verifies endpoint, key, model, vision input and JSON-shape compliance in
seconds using one 1×1 pixel image, with measured time to first byte and named
hints for 401, 402, 429 and 404.

## Key hygiene

Keys travel in environment variables (`--api-key="$OPENROUTER_API_KEY"`). They
are never hardcoded, printed or committed, and a key pasted into a chat, log or
screenshot is compromised and must be rotated. No report this harness writes
contains key material, verified by a tree scan.
