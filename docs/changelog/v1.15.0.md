# v1.15.0: tab-group sandbox and action verification integrity

## Tab-group sandbox

Every task runs inside a visible Chrome tab group, blue and titled with the
task. Privacy mode groups the task tab at the start, adopts the tabs the task
opens (`new_tab`, `target=_blank`, `window.open`), and bounds every tab action
(`switch_tab`, `close_tab`, `list_tabs`, `organize_tabs`) plus the capture
itself to the group's members.

Consequences worth stating:

- `list_tabs` no longer puts the titles and URLs of other browser tabs into the
  prompt.
- `organize_tabs` cannot regroup or close user tabs.
- If the visible tab drifts out of the group mid-run, the capture re-focuses the
  task tab instead of photographing a foreign page, and the sidebar records
  that.
- If the group becomes empty because the task tab was closed, the loop fails
  closed rather than wandering.

Shared logic is in `src/lib/tab-sandbox.js`; unit tests in
`scripts/test_tab_sandbox.mjs`.

## Action verification integrity

v1.14 added content, control and canvas signatures to the click verifier's
page-injected fingerprint, but the four helper functions lived outside the
injected function. `chrome.scripting.executeScript` serializes only the function
it is handed, so every click fingerprint threw inside the page and resolved to
null.

The hole was hidden by a Gmail-only mail-send probe that reported
`composeClosed=true` on any site, labelling unevaluated clicks as verified. The
field log on YouTube caught it.

v1.15.0 makes the fingerprint self-contained, host-gates the mail probe, and
adds a tab-level navigation lens for pages that are legitimately mid-teardown,
scoped so it cannot inflate a readable verdict.

The 10-scenario E2E-MOCK suite measures identically afterwards
(verifiedActionRatio 0.952, task success 1.0), now with real per-click evidence
(`e2e-benchmark-1788901453012.json`).
