# v1.17.0: Firefox support and byte-level line protection (2026-09-16)

## Firefox from one source tree

**Event-page backend** (`src/background/firefox-bg.js`). Firefox MV3 backgrounds
are classic-script event pages, not module service workers. The loader boots the
same `src/background/sw.js` module graph through dynamic `import()`, so one
source tree serves two runtimes with no forked logic.

**In-page ML runtime.** When `chrome.offscreen` is absent,
`src/lib/offscreen-client.js` hosts the same `src/offscreen/offscreen.html`
document in a hidden iframe inside the event page, which has a DOM, and talks to
it over a `window.postMessage` RPC bridge. The router in `offscreen.js`, the
envelope and the `rpcId` reply correlation are unchanged, so on-device models
run on Firefox with no duplicated ML code. Teardown mirrors the offscreen path:
an idle `OFFSCREEN_CLOSE_REQUEST` removes the iframe.

**Sidebar as a tab.** With `chrome.sidePanel` absent, the toolbar button opens
`src/sidepanel/sidepanel.html` in a regular tab, using the same UI modules.

**Build.** `scripts/build-firefox.mjs` (`npm run build:firefox`) copies `src/`,
`assets/` and `skills/` into `dist/firefox/` and rewrites the manifest:
event-page background, gecko id, and Chrome-only permissions dropped
(`sidePanel`, `offscreen`, `debugger`, `tabGroups`, `pageCapture`,
`readingList`). The build fails if any Firefox feature-detect guard has drifted
out of the source, with 10 guards checked.

**Degradation.** Trusted debugger clicks, the debugger screenshot fallback,
MHTML `save_page` and tab-group sandboxing all feature-detect at runtime, giving
clear errors or safe no-ops rather than TypeErrors.

## Line protection (`src/lib/wire-guard.js`)

Before each transmission, the exact serialized payload is scanned for:

- **Sensitive URL parameters.** `?token=`, `?api_key=`, `#access_token=` and 15
  more key names, matched in the byte stream, closing a credential-in-query leak
  class.
- **Key-shaped strings** in the serialized stream after JSON escaping, so a leak
  crafted to appear only inside string escapes is still caught.
- **Known raw values.** Values the pipeline just redacted are exact-matched
  against the bytes, so a detector miss upstream cannot survive.
- **Keys inside `data:` blocks.** Base64 data URLs are decoded and their
  printable runs scanned, so smuggled text cannot pass by obfuscation.

Every check is a hard predicate and callers must treat `{ ok: false }` as do not
transmit. No network failure produces a pass.

## URL cleanup and state gating

URLs persisted to storage (history, exports, per-model status) are scrubbed with
`scrubSensitiveUrlParams`, so sensitive query and fragment values and basic-auth
userinfo never reach `chrome.storage`; `sanitizeUrlForStorage` wraps it.

Persisted state is stamped with `STATE_VERSION`. At boot, settings written by a
newer build are reset to defaults, since this build cannot interpret a newer
schema, while older or unstamped state merges forward. History and export
entries from a future version are dropped on read. The stamp is build-owned and
caller values are ignored.
