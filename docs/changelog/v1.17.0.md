# v1.17.0 — Firefox Support + Byte-level Line Protection (2026-09-16)

## Firefox variant, derived from a single source tree

- **Event-page backend** (`src/background/firefox-bg.js`): Firefox MV3 backgrounds are
  classic-script event pages, not module service workers. The loader boots the SAME
  `src/background/sw.js` module graph via dynamic `import()` — one source tree, two
  runtimes, no forked logic to keep in sync.
- **In-page ML runtime** (`chrome.offscreen` functionality detection *without* the API):
  when `chrome.offscreen` is absent, `src/lib/offscreen-client.js` hosts the SAME
  `src/offscreen/offscreen.html` document in a hidden iframe inside the event page
  (event pages have a DOM) and talks to it over a `window.postMessage` RPC bridge —
  same router in `offscreen.js`, same envelope, replies correlated by `rpcId`.
  On-device models (Gemma 4 generation, vision warm-up, OCR, face detection) therefore
  run on Firefox with zero duplicated ML code. Teardown mirrors the offscreen path:
  the idle `OFFSCREEN_CLOSE_REQUEST` removes the iframe.
- **The sidebar opens as a tab**: with `chrome.sidePanel` absent, the toolbar button
  opens `src/sidepanel/sidepanel.html` in a regular tab (same module UI).
- **Built via `scripts/build-firefox.mjs`** (`npm run build:firefox`): copies `src/`,
  `assets/`, `skills/` to `dist/firefox/`, rewrites the manifest (event-page
  background, gecko id, Chrome-only permissions dropped: `sidePanel`, `offscreen`,
  `debugger`, `tabGroups`, `pageCapture`, `readingList`), and FAILS the build if any
  Firefox feature-detect guard has drifted out of the source (10 drift guards checked).
- **Honest degradation on Chromium-only APIs**: trusted (debugger) clicks, the
  debugger screenshot fallback, MHTML `save_page`, and tab-group sandboxing all
  feature-detect at runtime — clear error messages or safe no-ops, never TypeErrors.

## Line protection (`src/lib/wire-guard.js`)

Before each network transmission, scan the **exact serialized payload**:

- **Sensitive URL parameters** — `?token=`, `?api_key=`, `#access_token=` and 15 more
  key names, matched directly in the byte stream (a credential-in-query leak class).
- **Key-shaped strings** — secret-shaped text in the serialized stream, *post-JSON
  escaping*, so a leak crafted to appear only inside string escapes is still caught.
- **Known raw values** — the values the pipeline just redacted are exact-matched
  against the bytes; a detector miss upstream cannot survive this check.
- **Keys encoded within `data:` blocks** — base64 `data:` URLs are DECODED and their
  printable runs scanned, so smuggled text does not pass by obfuscation.

**Fail-closed**: every check is a hard predicate; callers MUST treat `{ ok: false }`
as "do not transmit". No network failure mode can produce a pass.

## URL parameter cleanup + obsolete state gating (`stateVersion`)

- **URL cleanup**: URLs persisted to storage (history, exports, per-model status
  blobs) are scrubbed via `scrubSensitiveUrlParams` — sensitive query/fragment values
  and basic-auth userinfo never touch `chrome.storage` (`sanitizeUrlForStorage`).
- **`stateVersion` gating**: persisted state is stamped with `STATE_VERSION`. At boot,
  settings written by a NEWER build are reset to defaults (this build cannot interpret
  newer schema) while older/unstamped state merges forward; history/exports entries
  from a future version are dropped on read. The stamp is build-owned — caller values
  are ignored.
