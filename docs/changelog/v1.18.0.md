# v1.18.0 — Task Authorization Daemon (2026-09-16)

Purchase/delete clicks require **explicit authorization from the user through their
own task text** ("Do not purchase anything" will also be blocked). Features include
**fault shutdown**, **injection prevention**, **overriding speculative queues**, and
a **3-hit honest exit**.

## The gate

`src/lib/task-guardian.js` (pure, regex-only, sub-millisecond) classifies every
planned action against a risk taxonomy — `purchase` (buy / add-to-cart / checkout /
pay / place order / subscribe / book / transfer / donate, EN + HI) and `deletion`
(delete / remove / trash / discard / clear / cancel / revoke / uninstall / wipe,
EN + HI) — on both the element label (click/submit/fill/type) and the URL
(navigate/new_tab → `/checkout`, `/delete`, …). `src/lib/guardian-daemon.js` wraps
it with the run-scoped policies and is invoked by BOTH agent loops (standard
`sw.js` execution loop and the privacy loop) before every **primary AND queued**
action, ahead of the approval gate and the executor.

- **Explicit authorization from the user's own text**: an occurrence of the risk
  class in the task text (or a mid-run note) authorizes it — negation-aware with a
  28-char before-window AND a Devanagari after-window (Hindi post-verbal negation,
  e.g. "खरीदो मत"), plus benign-context suppressions ("track my order", "payment
  status", "reading books") that never authorize.
- **"Do not purchase anything" is blocked too**: negated authorization = no
  authorization. The verdict carries an explicit FORBIDS message — the ban wins
  over any button the page shows.

## Fault shutdown

If the daemon itself throws (poisoned action shape, regex catastrophe), the verdict
is fail-closed `{ fatal: true }`: both loops terminate the task with an honest
terminal step + history entry instead of executing anything unverified. Nothing
risky runs while the gate cannot evaluate it.

## Injection prevention

The daemon's ONLY inputs are the user's **task snapshot** (pinned at run start —
`guardianTaskSnapshot()`; a mid-run mutation of the task text cannot authorize
anything after the fact) and the user's **own mid-run notes**. Page text, model
reasoning, and history are never passed as authorization evidence — an injected
page cannot talk, label, or re-caption its way past the gate.

## Overriding speculative queues

Queued ("speculative") actions execute without a fresh VLM turn, so the daemon
gates them identically — and a block **discards the remainder of the queue**
(`break` with the guardian hint overriding the next decision prompt). No risky
action can ride behind an approved one.

## 3-hit honest exit

Each blocked attempt counts against the run; the **3rd** block ends the task
honestly — DONE step + notification + `status: 'blocked'` history entry ("task
ended honestly; nothing risky was executed"), never an unauthorized execution.
A block costs the attacker the turn; the asymmetry is deliberate.
