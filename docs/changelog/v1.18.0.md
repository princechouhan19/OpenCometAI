# v1.18.0: task authorization daemon (2026-09-16)

Purchase and deletion clicks require explicit authorization from the user,
taken from their own task text. "Do not purchase anything" also blocks. The
release adds fault shutdown, injection prevention, overriding of speculative
queues, and an exit after three blocked attempts.

## The gate

`src/lib/task-guardian.js` is pure, regex-only and sub-millisecond. It
classifies every planned action against a risk taxonomy:

- **Purchase**: buy, add to cart, checkout, pay, place order, subscribe, book,
  transfer, donate, in English and Hindi.
- **Deletion**: delete, remove, trash, discard, clear, cancel, revoke,
  uninstall, wipe, in English and Hindi.

Classification reads both the element label for click, submit, fill and type
actions, and the URL for navigate and new-tab actions, matching paths such as
`/checkout` and `/delete`.

`src/lib/guardian-daemon.js` wraps it with the run-scoped policies. Both agent
loops invoke it before every primary and queued action, ahead of the approval
gate and the executor.

## Authorization comes from the user

An occurrence of the risk class in the task text, or in a mid-run user note,
authorizes it. Matching is negation-aware with a 28-character window before the
verb and a Devanagari after-window for Hindi post-verbal negation such as
"खरीदो मत". Benign contexts such as "track my order", "payment status" and
"reading books" never authorize.

A negated authorization is no authorization, so "Do not purchase anything"
blocks. The verdict carries an explicit forbid message, and the ban wins over
any button the page shows.

## Fault shutdown

If the daemon throws, on a poisoned action shape or a regex catastrophe, the
verdict is fail-closed `{ fatal: true }`. Both loops terminate the task with a
terminal step and history entry rather than executing anything unverified.

## Injection prevention

The daemon's only inputs are the task snapshot pinned at run start
(`guardianTaskSnapshot()`) and the user's own mid-run notes. Page text, model
reasoning and history are never passed as authorization evidence, so an
injected page cannot talk, label or re-caption its way past the gate. A mid-run
mutation of the task text cannot authorize anything after the fact.

## Speculative queues

Queued actions execute without a fresh model turn, so the daemon gates them
identically. A block discards the rest of the queue, with the guardian hint
overriding the next decision prompt, so no risky action rides behind an approved
one.

## Exit after three blocks

Each blocked attempt counts against the run. The third ends the task: DONE step,
notification, and a `status: 'blocked'` history entry recording that nothing
risky executed.

## Reference

The pattern was observed in SIH competitor research and reimplemented from
scratch with no shared code. In line with the project's anonymity policy, no
external source is cited here.
