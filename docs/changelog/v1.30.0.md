## 1. Per-test latency measured in EVERY benchmark test (P0-A)

Before v1.30.0 only the tier-level wall time (`durationMs` in `run-all.js`) and
the browser/e2e tiers' percentile summaries existed — the six Node unit suites
had **zero per-test timing**. v1.30.0 adds a shared latency helper and wires it
into every suite:

- **New `OpenCometBench/latency.js`** — `timed()` (per-case wall time),
  `latencyStats()` (n / min / p50 / mean / p90 / p95 / max / total), and
  `roundSamples()`. The percentile method matches the e2e/browser runners'
  `pct()` (sorted array, `floor(q·n)` index, clamped) so numbers are comparable
  across tiers. Empty or non-numeric sample sets report `n=0` — a missing
  measurement is never fabricated as 0.
- **All 6 unit suites individually timed** — privacy (every corpus case),
  redaction (every analytic step, `+stageMs` breakdown), visual-context (every
  page classification + worst-case gate decision), security (every test),
  fuzz (every case's full outbound path), server-validation (every test).
- **Adversarial e2e runner** times every case (`latencyMs` per row, printed in
  the live table and stored in the report JSON).
- **`run-all.js` prints a latency line per suite** and the `--json` output
  carries the FULL per-case sample arrays (`samplesMs[]`) — 815 samples total.

## 2. ROI-rescan activation — dead code wired into the OCR stage (P0-B)

`src/lib/roi-diff.js` (region-of-interest change detection — pure,
dependency-free, unit-testable) had been complete but **unwired** since its
authoring. v1.30.0 activates it as the OCR stage's partial re-scan driver:

- `privacy-filter.js` keeps a **fingerprints-only chain state** (`_roiState`):
  block fingerprints (mean/variance/gradient energies over a 96×54 grayscale
  proxy) + the OCR regions valid on those pixels. No pixels are retained — the
  statistics cannot reconstruct the screen.
- On an OCR-memo miss, `planRoiRescan()` diffs fingerprints and decides FULL
  vs region-only re-scan. **Fail-toward-full on every guard**: first sight,
  URL change, capture-dims change, changed-ratio over cap, periodic full cap,
  coverage cap, and ANY computation error.
- ROI mode re-OCRs **only the changed regions** (via the new STRICT
  `scanImagePiiRegionsRoi` in `ocr-pii.js` — ×2-upscaled crops, decode
  failure / zero-scanned THROWS → caller degrades to full scan); previous
  regions fully outside every scanned region are kept
  (`boxOutsideAllRegions`), stale boxes never survive on changed pixels.
- `changedCount = 0` (re-encode noise on an exact-string memo miss) reuses ALL
  previous regions — no scan at all.
- Failed/skipped scans reset the chain; `cfg.roiRescan` (default ON) is the
  fail-safe switch; `stats.roi` telemetry + honest `roiMode=roi/full` log lines.

### Measured ROI decision overhead (Node, this release)

Fingerprints + diff + plan + region planning: **0.095 ms/frame** — four orders
of magnitude below the reference-hardware full-page OCR leg (~3402 ms, the
cost ROI mode avoids on partially-changed frames). The ROI path's end-to-end
OCR timing lands in `stats.roi.scanMs` on every live frame; browser-tier
before/after numbers are the browser tier's to publish (the unit tier does not
run the OCR engine).
