# v1.16.0 — Local-perception cost round

> Release notes for **v1.16.0** (moved out of the README; content preserved verbatim from the release section).

The v1.15.9 real-VLM evidence exposed the true bottleneck: the measured
`sanitizeMs 41487` is dominated by a **one-time cold-cache model load** (the
same report family measured `vitLoadMs 37873` on this hardware), not by
steady-state perception. v1.16.0 attacks the cost structure at all three
latency conditions — and refuses to merge them:

| Condition | Definition | Measured | v1.16.0 change |
|---|---|---|---|
| ① Cold first step | fresh profile → model download + compile + first inference | ViT load alone 37873 ms; real-VLM first-step sanitize 41487 ms | **Session warm-up** (`VISION_WARMUP`): YOLO + ViT pipelines load in the offscreen runtime the moment a privacy session starts, fire-and-forget, non-fatal — the first capture pays inference only |
| ② Warm unchanged screen | byte-identical capture, detector memo hits | sanitize P50 1216 ms — of which OCR re-scanned every time (1120 ms) | **OCR memo** (v1.16.0): exact-capture + ROI-keyed, region boxes only, failed/skipped scans never cached, `cfg.ocrMemo=false` fail-safe, `ocrMemoHit` telemetry — the OCR leg collapses to ≈0 ms on unchanged screens |
| ③ Changed frame | any pixel change → memo MISS → full re-detection | 12885 ms wall (YOLO 7841 + OCR 3402) | Memo + warm-up shorten the re-hit path; the YOLO re-detection cost itself is untouched by design (privacy semantics) |

**Honest negative result, measured:** the hypothesized "run YOLO on a downscaled
copy" optimization was probed (`OpenCometBench/probe-yolo-downscale.mjs`) and
**refuted**: box parity is perfect (all-class IoU = 1.000, identical detections
on every fixture), but latency is neutral (~0.99×) — yolos-tiny resizes
internally to a fixed resolution, so input size does not drive compute. The
`yoloMaxEdge` knob ships disabled (`0`) with the probe archived; the changed-frame
YOLO cost is addressed by the memo + warm-up levers instead, and further
reduction (region-of-interest re-detection) remains future work.

**`run-e2e-real.mjs --warmup`** runs one unmeasured sanitize cycle (zero VLM
calls, zero API cost) before the measured scenarios and stamps `meta.warmup`, so
real-VLM reports describe the steady state while the cold-start condition stays a
separately named row. The built-in **10-scenario matrix** (`--only` accepts a
comma-separated subset) is now documented as the SIH evidence block it was always
meant to be.
