# v1.16.0: the local perception cost round

The v1.15.9 real-model evidence located the bottleneck: `sanitizeMs 41487` is
dominated by a one-time cold-cache model load, with `vitLoadMs 37873` on the
same hardware, not by steady-state perception. This release attacks all three
latency conditions separately and refuses to merge them.

| Condition | Definition | Measured | Change |
|---|---|---|---|
| Cold first step | Fresh profile, model download, compile, first inference | ViT load alone 37873 ms; first-step sanitize 41487 ms | Session warm-up (`VISION_WARMUP`): YOLO and ViT pipelines load in the offscreen runtime when a privacy session starts, fire and forget, non-fatal, so the first capture pays inference only |
| Warm unchanged screen | Byte-identical capture, detector memo hits | Sanitize p50 1216 ms, of which OCR re-scanned every time at 1120 ms | OCR memo: keyed on exact capture plus regions, region boxes only, failed and skipped scans never cached, `cfg.ocrMemo=false` as a fail-safe, `ocrMemoHit` telemetry. The OCR leg collapses to about 0 ms on unchanged screens |
| Changed frame | Any pixel change, memo miss, full re-detection | 12885 ms wall time (YOLO 7841 + OCR 3402) | The memo and warm-up shorten the re-hit path; YOLO re-detection cost is untouched by design, for privacy reasons |

## Measured negative result

The hypothesis that YOLO could run on a downscaled copy was tested with
`OpenCometBench/probe-yolo-downscale.mjs` and refuted. Box parity is perfect
(all-class IoU 1.000, identical detections on every fixture) but latency is
neutral at about 0.99×, because yolos-tiny resizes internally to a fixed
resolution, so input size does not drive compute.

The `yoloMaxEdge` setting ships disabled at 0 and the probe is archived. The
changed-frame YOLO cost is addressed by the memo and warm-up, and further
reduction through region-of-interest re-detection remains future work.

## Harness

`run-e2e-real.mjs --warmup` runs one unmeasured sanitize cycle, with no model
calls and no API cost, before the measured scenarios, and stamps `meta.warmup`.
Real-model reports therefore describe the steady state while cold start remains
a separately named row.

The built-in 10-scenario matrix, where `--only` accepts a comma-separated
subset, is now documented as the evidence block it was meant to be.
